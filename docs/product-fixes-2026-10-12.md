## 本轮追加的界面细节修复

- 固定标题、状态、类别、筛选项、表单、通知和已知审计动作统一中文显示。移除 Gotchas / Findings、Display Name、Project ID、Danger Zone 等重复英文标签；真实标识、文件路径、品牌及 MCP / P0 等必要名称保持原意。
- 按钮、表头、状态徽标和短计数保持完整文字；空间不足时由父容器换行或内部滚动。反馈次数拆成“反馈、下发、已知”三个完整短行，避免把“已知”拆开。
- 缩短录入需求说明，修复末行只剩“手”的情况；固定说明采用平衡换行；规则适用检查标题不再把“查”挤到下一行。视觉脚本检查固定标题/说明的末行孤字及短控件拆行。
- 桌面任务/规则抽屉加宽至 720px；审阅条款与反馈便签在空间不足时上下排布。移动端减少多层边框内距，让正文用足宽度。
- 窄屏删除项目输入框和确认按钮上下排列；修正任务抽屉流转按钮被关闭按钮样式误放大的问题；打开动画结束后检查关闭按钮可见和可点击。
- 移除全局说明文字的强制大写，避免提案、任务标识被展示为与原数据不同的大小写。长说明允许自然换行，需求原文保留段落。
- 审计动作映射按后端真实事件名校正；分页过程中刷新账本会清除旧加载状态，旧响应不会污染新列表。

正文宽度为浏览器渲染后的内容区域实测值，而非 CSS 声明值：

| 视口 | 审阅条款正文 | 开发便签正文 | 布局 |
| --- | ---: | ---: | --- |
| 1440 × 900 | 474px | 500px | 双列 |
| 1280 × 720 | 860px | 918px | 上下排列 |
| 768 × 1024 | 674px | 690px | 上下排列 |
| 390 × 844 | 296px | 312px | 上下排列 |

以上宽度来自当前合成数据和默认缩放。任意用户正文仍允许正常换行，不承诺所有自然文本都没有短尾行。

## 完成度边界

本轮验收覆盖已复现缺陷及修复引入的关键边界，不等同于产品全部 256 项能力、所有设备或所有输入组合均已完成。G01–G12 仍应按原报告安排；本轮虽顺带补了审计详情和部分请求状态管理，也没有把对应能力建议整体标为完成。

移动端检查使用桌面 Chromium 模拟视口，屏幕阅读器、实体移动设备、跨机器连接和生产数据迁移未在本轮验证。现有历史库若已被旧导入脚本写成缺版本快照状态，新导入会明确拒绝并提示修复；本轮没有自动改写历史业务数据。

## 用户指定的 pi 提示词讨论

已读取会话 `01a132a1-aeb9-7081-a4e9-61068728ff58` 的用户与助手可见消息。其讨论对象是 MCP 静态 instructions / tool descriptions，当前实现为一段服务说明和 17 个工具。用户最后强调 Debug 评分和问题报告工具应主动提供真实反馈。

讨论中的建议需要与现有契约对齐：任务没有 completed 状态；规则类别只有 business / security / gotcha；0 分不代表所有规则都会压缩，P0 保留完整；已知标记与会话、规则版本关联，评分需要真实下发记录，不能对同一次下发改分刷次数；冲突报告还受任务绑定和同作用域约束。MCP 工具描述如何进入模型上下文由客户端决定，不是协议保证的一次性系统提示词注入。

本轮没有按该讨论全面改写 MCP 提示词或放宽规则匹配策略；仅保留审查缺陷修复中对 Debug 门槛的准确说明。涉及产品策略的提示词修改应同步核对产品契约。
