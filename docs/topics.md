# 主题与规则查询

Topic 是项目内有定义的业务词表，不是自由标签。Agent 使用前查询已有定义，显式创建新词条；不能根据规则文本自行登记主题。

## 查询

```python
codeneuro_get_context(
    project_id="archive",
    task_id="明确选中的任务ID",  # 项目级操作可以省略
    priorities=["P0", "P1"],
    topics=["volume-revision"]
)
```

priorities 必填、非空、不重复，只允许 P0–P3，是明确集合而非阈值。topics 和真实相对文件至少提供一种；files 与 file_path 二选一。

| 条件 | 非全局规则准入 | 文件作用 |
| --- | --- | --- |
| 有主题，没有文件 | 任一主题相交 | 无 |
| 有主题，也有文件 | 任一主题相交 | 仅辅助排序 |
| 无主题，有文件 | 命中规则的路径范围 | 准入及排序 |
| 主题和文件均为空 | 参数错误 | 不回退为全项目广播 |

先检查项目、明确 Task、活跃状态和所选等级，再判断适用性。is_global 明确表达全局规则，但仍受项目、Task 可见性、状态和所选等级约束；空主题或空路径不隐式等于全局。P0 也不是全局标记。

已选中且适用的全文形态 P0 保持正文完整；card 规则完整列入本次查询的轻量目录，每项提供编号、版本、标题和使用时机，不含正文。Agent 根据当前任务及下一步操作自主读取相关正文，无需用户逐条选择；目录提示不是当前要求。目录仍遵循上述项目、Task、主题、路径和等级匹配，不扩展为全项目广播。预算只约束完整条款与头部，目录不按数量或总字数截断，也不计入 budget_exceeded。评分不改变等级或适用性，0 分不压缩后续内容。父需求与本任务范围独立下发，不受规则等级选择隐藏；省略信息明确记录。Finding 仍为本 Task 的未审阅观察。

## 词条维护

Topic 字段为 project_id、key、name、description、version、status、definition_locked。

- key 是项目唯一的小写 slug，最多 64 字符；不可改名，删除后也不复用。
- description 定义业务边界。尚无引用时可修订；首次被规则、Finding 或提案引用后锁定。
- 锁定后只允许修改显示名；业务含义改变需要新 Topic，并显式重新分类相关知识。
- 删除使用 expected_version 与原因，同事务检查活跃/草稿规则、待审阅 Finding 和未决提案。存在引用则阻断，不自动摘除、转移或合并。
- 历史快照和实际下发保持原内容。查询未知或已删除主题报错，不静默换成文件模式。

Topic CRUD 均直接给 project_id：list_topics、get_topic、create_topic、update_topic、delete_topic。列表按稳定 key 分页，默认 50、最多 100，支持搜索和 include_deleted。get 的 include_usage 可返回当前阻断统计及有界引用摘要。

HTTP 资源位于 `/api/projects/{project_id}/topics`。启用主题查询使用 `/topics/enable`，携带 expected_revision 与确认原因。

## 覆盖检查

项目尚未确认分类完整时，文件查询仍可使用，主题查询被阻断。当前活跃规则需要明确主题或全局性、P0 理由和验证依据；待审阅 Finding 需要合法主题。

缺少验证计划的存量规则可从工作台分类，填写真实规范依据；已有计划的规则继续走正常治理，不能借分类绕过测试。覆盖满足后明确启用主题查询。主题匹配不会自动纠正过宽的路径范围。

检索范围与验证证据独立。无路径规则不需要伪造文件锚点；测试计划与人工规范分别走其验证流程，详见[规则治理](governance.md)。
