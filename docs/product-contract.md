# 产品契约

CodeNeuro 为 Coding Agent 提供项目业务目标、独立任务范围和适用规则。Hub 保存知识、下发与证据；宿主负责文件、编码、测试和用户确认。

## 业务目标与任务

- 固定层级为 Project → Requirement → Task，不使用原子任务树或聊天会话表达业务层次。
- Requirement 状态为 draft、active、accepting、completed；Task 状态为 draft、active、testing、paused、completed。
- Task 开发完成先进入 testing，提供验证结论后才进入 completed。可选报告必须属于本 Task 且验证成功。
- 所有未删除子任务完成后，父需求进入 accepting，必须经过用户明确整体验收才进入 completed。空需求不能完成。
- 新增、重开或修改子任务范围使已有验收准备失效。已完成父需求先重开再开发；暂停恢复到原状态。
- 归档只负责收纳；未完成的归档任务仍阻断验收。删除是撤回范围，保留历史，不表示完成。
- 更新和删除使用当前 `expected_version` 与原因，防止静默覆盖。旧正文、修订与实际 Delivery 不被改写。

## 上下文

- 直接提供项目与可选 Task，没有 Session 生命周期或必建执行句柄，不从 Worktree、source 或最近请求猜任务。
- Task 上下文包含父需求与本任务，不混入兄弟任务。错误、跨项目或已删除 Task 不静默回退到项目级查询。
- 显式选择 P0–P3；主题或具体相对文件至少有一种。有主题按主题准入，无主题按路径准入。全局性必须显式声明。
- 被选中且适用的全文形态 P0 保持正文完整，未被选择或不适用的 P0 不强行加入。预算、省略、匹配依据都明确返回。
- 规则的查询形态由规则自身声明：完整条款，或按需读取的轻量目录项。目录完整列出本次匹配到的 card 规则，提供编号、版本、标题和使用时机，不加载正文，也不按数量或总字数截断。Agent 根据当前任务及下一步操作自主读取相关正文，不要求用户逐条选择，不默认加载无关正文；目录提示不是当前要求。正文版本绑定该次下发，目录与取用分别记录；正文预算及超限标志不计算目录。
- 相同 request_id 与相同输入重放当时结果；变更输入冲突，新 ID 获取当前知识。Delivery 查询只读实际记录。
- 评分 0 是“已知”的统计，不压缩后续 Agent 的正文。评分和 Issue 无 debug 前置。

## 规则、主题与证据

Topic 是项目受控词表。稳定 key 不复用，引用后业务边界锁定；删除检查当前引用，不自动摘除关系或重新分类。按当前覆盖状态明确启用主题查询。

Task Rule 可以由不同 Agent 接续。可测试规则声明检查、条款索引和测试 ID；激活需按检查覆盖的独立成功事件且满足既有置信度约束。相同事件更换 Agent、请求 ID、顺序或等价时间区不增加权重。规范规则需明确审阅依据。

Rule 晋升原样复制有效候选；修改已有长期契约仍需人类审阅固定目标与候选。任务单独完成后，短期规则可服务整体验收；整体完成、归档或删除相应范围时停用。重开不自动恢复规则。

Finding 是未审阅观察，按 Task 和主题/文件读取；不能自动变成 Rule。Issue 是待处理报告，不能冒充已裁决冲突。

## 实现边界

MCP 返回一段 JSON 文本，不重复正文；列表和修订历史分页，账本聚合统计不依赖第一页长度。HTTP 与 MCP 共用用例。

产品只维护当前模型和接口，空库直接建表，本地旧数据由一次性脚本转换。记录 `version` 仅用于并发与正文追溯，不承担软件版本选择。

无鉴权。actor、human、Worktree 和接受确认的原因都不能证明真实用户身份。Hub 不执行测试、不编辑工作区、不拦截宿主工具。安装 MCP 本身不等于模型会自动查询。
